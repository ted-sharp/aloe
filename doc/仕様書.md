## 1. 概要

### 1.1 目的

RazorReportDesignerは、Blazor Serverアプリケーション（WPF WebView2でホスト）でWYSIWYG（What You See Is What You Get）方式のレポートデザイナーを提供します。JSON形式でレイアウトデータを保存し、Microsoft純正Razorエンジンでパラメータを渡してHTMLに変換し、WebView2でプレビューを表示します。完成したレポートはPlaywrightによるPDF変換で出力できます。

### 1.2 主な機能

- **Blazorベースの WYSIWYG デザイナー**: Blazor Razorコンポーネントによるドラッグ&ドロップで直感的にレポートをデザイン
- **Microsoft 純正 Razor エンジン**: Blazor組み込みのテンプレートエンジンによる柔軟なデータバインディング
- **プレビュー機能**: Blazor コンポーネント + WebView2によるHTMLプレビュー表示（リアルタイム更新）
- **PDF出力**: Playwright によるPDF変換（高度なレイアウト制御に対応）
- **グリッドシステム**: A4ベースのグリッド分割による整ったレイアウトのためのスナップ機能
- **リッチテキスト編集**: フォント、スタイル、色などの詳細なテキスト編集

### 1.3 対象ユーザー

- レポートデザイナー
- 開発者
- ビジネスユーザー（基本的な操作が可能なユーザー）

### 2.3 システム境界

- **入力**: ユーザーのマウス・キーボード操作（Blazor UI経由）、ファイル読み込み
- **出力**: JSONファイル（.rrd / .json）、PDFファイル
- **通信**: SignalR（Blazor Server ↔ WebView2、localhost内なので遅延なし）
- **中間生成物**: Razorテンプレート（メモリ上でのみ生成、直接保存はしない）
- **外部依存**: WebView2ランタイム、Blazor Server ランタイム、Playwright Chromium

- **デザインビュー**: レポートのレイアウト編集モード（HTML5 Canvas または SVGで描画）

  - グリッド表示

- HTMLは直接編集不可（WYSIWYGのみ）

#### 3.1.3 レイアウト作成時のデータ表示方法

レイアウト作成時には、デザインビュー内で2種類の表示方法を切り替え可能：

**1. 仮組みモード（プレースホルダー表示）**:
- 実際の値が入っていない状態でコンポーネントを配置
- テキストコンポーネント: プレースホルダーテキスト（例: "テキスト"）を表示
- 画像コンポーネント: プレースホルダー画像を表示
- データバインディング部分（`@dic["key"]`等）: Razorコードそのまま表示
- レイアウトの構造を確認しながらデザイン可能

**2. データ表示モード（サンプルデータ表示）**:
- サンプルデータを適用した状態でレイアウト
- テキストコンポーネント: サンプルテキストを表示
- 画像コンポーネント: サンプル画像を表示
- データバインディング部分: サンプルデータで評価された結果を表示
- 実際のレポートに近い見た目でレイアウトを確認可能

**モード切り替え**:
- ツールバーのボタンで両モードを切り替え可能
- デザインエリア内でリアルタイムに表示が切り替わる
- 両モードともWYSIWYG方式で編集可能

**注意**:
- デザインビューはSkiaCanvasで描画されるため、HTMLプレビューではない
- プレビュービューで、実際のHTML/PDFの見た目を最終確認

### 3.2 デザイナー機能

#### 3.2.1 グリッドシステム

##### グリッド分割方式

- **基本方針**: A4サイズを基準とした36列固定分割システム
- **保存形式**: グリッドセル単位（column, row, columnSpan, rowSpan）で位置とサイズを記録
- **基本分割数**: 36列（固定）
- **表示分割数**: 36, 30, 24, 18列の中から選択可能（appsettings.jsonで設定）
- **表示分割数の役割**: デザインビューの視覚的表現のみに使用。内部データは常に36列基準で管理

##### A4サイズとグリッド分割

**A4サイズ（96dpi基準）**:
- 幅: 793.7px（210mm）
- 高さ: 1122.52px（297mm）

**基本グリッド（36列固定）**:
- 列幅 = 793.7 ÷ 36 = 22.05px
- 行高 = 列幅（正方形に近づけるため）= 22.05px
- 行数 = 1122.52 ÷ 22.05 = 51行（四捨五入）

**表示用グリッド（36, 30, 24, 18列の選択肢）**:

| 列数 | 列幅（px） | 行数 | 行高（px） |
|------|-----------|------|-----------|
| 36列 | 22.05 | 51行 | 22.05 |
| 30列 | 26.46 | 42行 | 26.46 |
| 24列 | 33.07 | 34行 | 33.07 |
| 18列 | 44.09 | 25行 | 44.09 |

**計算方法**:
- 列幅 = A4幅 ÷ 列数
- 行高 = 列幅（セルが正方形に近くなるように統一）
- 行数 = A4高さ ÷ 行高（四捨五入）

**注意**: 内部データはすべて36列基準で保存される。表示時に選択された分割数で視覚的に表示される。座標変換はスケーリング計算で対応。

##### グリッド表示

- **表示方法**: デザインビューに背景グリッドを表示
- **デフォルト状態**: グリッド罫線はデフォルトでON（表示状態）
- **表示/非表示**: ツールバーのトグルボタンで切り替え可能（デフォルトはON）
- **視覚的表現**: 点線または薄い線で表示（グリッド罫線）
- **分割数切り替え**: ツールバーまたはメニューから分割数を選択可能（36, 30, 24, 18）
- **表示のみ切り替え**: グリッドの表示/非表示は分割数の変更とは独立して切り替え可能

##### スナップ機能

- **動作**: 要素を配置・移動する際に、グリッドセルの境界に自動的にスナップ
- **スナップ有効/無効**: 常に有効（オフにできない）
- **スナップ単位**: 現在選択されている分割数のグリッドセル単位
- **スナップ方式**: 必ずグリッドセルに吸い付くようにスナップ（強制スナップ）
- **実装**: 要素の位置とサイズは常にグリッドセル単位に丸められる

##### セルベースの配置

- **配置単位**: グリッドセル単位で配置
- **位置指定**: セルの列位置（column）と行位置（row）で指定
- **サイズ指定**: セルの幅（columnSpan）と高さ（rowSpan）で指定
- **制約**: すべてのコンポーネントの位置とサイズはグリッドセル単位で管理

##### グリッド範囲選択機能

**基本的な範囲選択**:
- **選択方式**: Excelのようにグリッドの範囲を選択可能
- **操作方法**: デザインエリア上でマウスをドラッグしてグリッドセルの範囲を選択
- **視覚的表現**: 選択された範囲をハイライト表示（半透明の矩形）
- **選択範囲の表示**: 選択された範囲の列数と行数を表示（例: "12列 × 5行"）

**用途1: コンポーネント貼り付け**:
- 操作手順:
  1. グリッド範囲を選択
  2. ツールパレットからコンポーネント（テキスト、画像等）を選択
  3. 選択された範囲にコンポーネントが配置される
- **配置サイズ**: 選択された範囲のサイズ（columnSpan, rowSpan）に合わせて自動的に配置
- **位置**: 選択範囲の左上のセル（column, row）に配置

**用途2: テーブル作成**:
- 操作手順:
  1. グリッド範囲を選択
  2. ツールバーの「テーブル作成」ボタンをクリック
  3. 選択された範囲にテーブルコンポーネントが作成される
- **テーブルサイズ**: 選択された範囲の列数と行数に合わせてテーブルが作成される
- **位置**: 選択範囲の左上のセル（column, row）に配置
- **セル数**: 選択範囲の列数 × 行数のセルを持つテーブルが作成される

##### 実装詳細

- 要素の配置時: 必ずグリッドセルの境界にスナップ（強制）
- 要素の移動時: ドラッグ中も必ずグリッドセルにスナップ（強制）
- 要素のリサイズ時: リサイズハンドルをドラッグする際も必ずグリッドセル単位でリサイズ（強制）
- グリッド罫線の描画: 選択された分割数に応じて縦横の罫線を描画（背景レイヤー、デフォルトON）
- 保存形式: JSONにはセル位置（column, row）とセルサイズ（columnSpan, rowSpan）を保存
- 範囲選択: マウスドラッグでグリッドセルの範囲を選択し、選択範囲をハイライト表示

- 初期状態は空のセル

**グリッド範囲選択から作成**:
- グリッド範囲を選択した状態で「テーブル作成」ボタンまたは「枠線表示」ボタンをクリック
- 選択された範囲の列数 × 行数のセルを持つテーブルが作成される
- 選択範囲の左上のセル位置に配置される

**テンプレートから**:
- 事前定義されたテーブルテンプレートを使用
- テンプレート例:
  - 請求書テーブル
  - 見積書テーブル
  - 一覧表
  - カレンダー形式

##### データバインディング方式

**方式1: 配列データの繰り返し表示**

- 配列データをJSON文字列として`Dictionary<string, string>`に渡す
- Razorテンプレート内でJSON文字列をパースして使用
- セル内で `@item.PropertyName` でプロパティにアクセス
- 例: 顧客リスト、商品一覧など

**実装例**:
```razor
@{
    var items = JsonSerializer.Deserialize<List<Item>>(Model["items"]);
}
<table>
    <thead>
        <tr>
            <th>商品名</th>
            <th>数量</th>
            <th>単価</th>
            <th>金額</th>
        </tr>
    </thead>
    <tbody>
        @foreach(var item in items)
        {
            <tr>
                <td>@item.ProductName</td>
                <td>@item.Quantity</td>
                <td>@item.UnitPrice</td>
                <td>@(item.Quantity * item.UnitPrice)</td>
            </tr>
        }
    </tbody>
</table>
```

**方式2: 個別値の配置**

- 各セルに個別の値を配置
- パラメータ参照: `@dic["key"]` 形式
- ドラッグ&ドロップでパラメータパネルから値を配置可能

##### テーブル編集機能

**行・列の操作**:
- 行の追加（上/下）
- 行の削除
- 列の追加（左/右）
- 列の削除
- **重要**: テーブル内で行・列を追加・削除しても、テーブル全体のサイズ（columnSpan, rowSpan）は自動的には変更されない
- セルが小さくなるか、領域内に収まらなくなる
- テーブルのサイズを増やすには、ユーザーがリサイズハンドルでテーブル全体をリサイズする必要がある

**セルの操作**:
- セルの結合（colspan、rowspan）
- セルの分割
- セルの内容編集
- **注意**: セルの結合・分割時も、テーブル全体の位置とサイズはグリッドセル単位に準拠

**スタイル設定**:
- セル背景色
- ボーダー（太さ、色、スタイル）
- パディング
- テキスト配置（左、中央、右、両端）

**ヘッダー行の設定**:
- ヘッダー行の指定
- ヘッダー行のスタイル設定

**グリッドセル準拠**:
- テーブル全体の位置とサイズはグリッドセル単位で管理（column, row, columnSpan, rowSpan）
- テーブル内部のセルサイズは、テーブル全体のサイズに応じて自動的に計算される
- 最小セルサイズはグリッド1セル相当（テーブルが1列1行の場合、セルサイズはグリッド1セル）

#### 3.2.6 オブジェクトスナップ機能（将来拡張）

##### オブジェクト間スナップ（将来拡張）

**注意**: この機能は将来拡張予定です。以下の仕様は参考情報として記載しています。

- **動作**: Altキーを押しながらコントロールをドラッグすると、他のコントロールにスナップ（グリッドスナップは常に有効のまま）
- **スナップ対象**: 
  - 他のコントロールの端（上、下、左、右）
  - 他のコントロールの中心点
  - 他のコントロールの角
- **視覚的フィードバック**: スナップ時にガイドライン（青い線）を表示
- **スナップ範囲**: マウスカーソルがスナップ対象の±4px以内の場合にスナップ

##### グリッドスナップとの関係

- **基本方針**: グリッドスナップは常に有効（オフにできない）
- **Altキー押下時**: オブジェクト間スナップも有効になるが、最終的な位置は必ずグリッドセルにスナップ
- **優先順位**: グリッドスナップが最優先。オブジェクト間スナップは補助的な位置合わせに使用

##### 実装詳細（参考）

- Altキーの検出: `Keyboard.IsKeyDown(Key.LeftAlt)` または `Keyboard.IsKeyDown(Key.RightAlt)`
- スナップ判定: ドラッグ中のコントロールの位置と他のコントロールの位置を比較
- ガイドライン表示: スナップ時に一時的にガイドラインを描画
- 最終位置: オブジェクト間スナップで計算された位置も、必ずグリッドセル単位に丸める

### 3.3 レイアウトデータ管理

#### 3.3.1 保存形式

- **ファイル形式**: JSON形式で保存
- **ファイル拡張子**: `.rrd`（RazorReportDesigner）または `.json`
- **エンコーディング**: UTF-8
- **管理方式**: Razorファイルとして直接管理せず、JSONで管理

#### 3.3.2 JSON構造

レイアウトデータは以下のようなJSON構造で保存します：

```json
{
  "version": "1.0",
  "grid": {
    "columns": 36,
    "rows": 51,
    "columnWidth": 22.05,
    "rowHeight": 22.01
  },
  "pageSize": {
    "width": 793.7,
    "height": 1122.52,
    "unit": "px",
    "dpi": 96
  },
  "elements": [
    {
      "type": "TextElement",
      "id": "text-1",
      "position": {
        "column": 0,
        "row": 0,
        "columnSpan": 12,
        "rowSpan": 2
      },
      "properties": {
        "text": "サンプルテキスト",
        "fontFamily": "Noto Sans JP",
        "fontSize": 16,
        "color": "#000000",
        "backgroundColor": "#FFFFFF",
        "textAlign": "left",
        "styles": {}
      },
      "customProperties": {}
    },
    {
      "type": "ImageElement",
      "id": "image-1",
      "position": {
        "column": 0,
        "row": 2,
        "columnSpan": 18,
        "rowSpan": 9
      },
      "properties": {
        "imagePath": "sample.jpg",
        "sampleImagePath": "sample_placeholder.jpg",
        "aspectRatio": true
      },
      "customProperties": {}
    },
    {
      "type": "TableElement",
      "id": "table-1",
      "position": {
        "column": 0,
        "row": 11,
        "columnSpan": 36,
        "rowSpan": 10
      },
      "properties": {
        "rows": 5,
        "columns": 4,
        "borderWidth": 1,
        "borderColor": "#000000"
      },
      "customProperties": {}
    }
  ],
  "metadata": {
    "createdAt": "2026-01-23T00:00:00Z",
    "updatedAt": "2026-01-23T00:00:00Z",
    "gridColumns": 36
  }
}
```

##### JSON構造の説明

**ルートレベル**:
- `version`: JSONフォーマットのバージョン
- `grid`: グリッド設定（列数、行数、セルサイズ）
- `pageSize`: ページサイズ情報（A4基準）
- `elements`: 配置された要素の配列
- `metadata`: メタデータ

**gridオブジェクト**:
- `columns`: 列数（保存時は常に36、表示用の分割数は`metadata.gridColumns`に保存）
- `rows`: 行数（列数に応じて計算された値、36列基準）
- `columnWidth`: 1列の幅（px、36列基準）
- `rowHeight`: 1行の高さ（px、36列基準）

**elements配列の各要素**:
- `type`: 要素の種類（TextElement, ImageElement, TableElement等）
- `id`: 要素の一意な識別子
- `position`: グリッドセルベースの位置情報
  - `column`: 開始列位置（0始まり）
  - `row`: 開始行位置（0始まり）
  - `columnSpan`: 占有する列数
  - `rowSpan`: 占有する行数
- `properties`: 要素固有のプロパティ（型ごとに異なる）
- `customProperties`: 任意のカスタムプロパティ（拡張用）

**位置情報の計算**:
- 実際のピクセル位置 = `column * columnWidth`（X座標）
- 実際のピクセル位置 = `row * rowHeight`（Y座標）
- 実際のピクセル幅 = `columnSpan * columnWidth`
- 実際のピクセル高さ = `rowSpan * rowHeight`

#### 3.3.3 JSONからHTML/Razorへの変換

- **変換タイミング**: プレビュー表示時、PDF出力時、エクスポート時
- **変換処理**: JSONデータを読み込み、HTML/Razorテンプレートに変換
- **変換サービス**: `LayoutToRazorConverter` サービスが担当
- **出力形式**: 変換後のRazorテンプレートは一時的にメモリ上に保持、または一時ファイルとして保存

##### 変換処理の詳細

**1. JSON読み込み**:
- JSONファイルを読み込み、デザインモデルに変換
- グリッド情報（列数、行数、セルサイズ）を取得
- 各要素の位置情報（column, row, columnSpan, rowSpan）を取得

**2. Razorテンプレート生成**:
- 各要素をHTML/Razorコードに変換
- **位置情報の実現方式**: CSSグリッドレイアウトを使用
  - グリッド内の位置は `grid-column` と `grid-row` で指定
  - 例: `grid-column: column-start / span columnSpan; grid-row: row-start / span rowSpan;`
  - これにより、JSONで保存されたセル単位の情報をそのままCSSに反映
  - ピクセル計算は不要（CSSエンジンが自動処理）
- 要素固有のプロパティをスタイルや属性として反映
- カスタムプロパティも可能な限り反映

**3. HTML変換**:
- Razorテンプレートにパラメータを適用
- HTMLを生成

**4. 出力**:
- WebView2でプレビュー表示
- またはPDFとして出力

**メリット（CSSグリッドを使用する理由）**:
- セル単位で保存されたデータをそのままCSSグリッドで配置可能
- ピクセル単位の計算が不要で、エラーが少ない
- グリッド分割数を変更した場合、CSSの自動レイアウト機能により自動的に再配置
- レスポンシブデザインへの拡張が容易

#### 3.3.4 変換処理の流れ

```
JSONファイル（.rrd）
    ↓
JSON読み込み
    ↓
グリッド情報取得（列数、行数、セルサイズ）
    ↓
要素の位置情報取得（column, row, columnSpan, rowSpan）
    ↓
デザインモデル（DesignElement等）
    ↓
Razorテンプレート生成（CSSグリッド配置）
    ├─ グリッドコンテナ設定
    ├─ 各要素に grid-column / grid-row を適用
    └─ CSSエンジンが自動的にセル配置を計算
    ↓
HTML変換（パラメータ適用）
    ↓
WebView2表示 / PDF出力
```

### 3.4 Razorテンプレート

#### 3.4.1 生成方式

- **生成元**: JSONデータから自動生成
- **テンプレートエンジン**: Microsoft純正Razorエンジン（Blazor Server組み込み）
- **保存**: 直接保存はしない（JSONから都度生成）
- **一時処理**: メモリ上でテンプレートを生成・処理（一時ファイル不要）
- **メリット**: RazorLight等のサードパーティライブラリ不要、.NET標準機能として長期サポート

#### 3.4.2 パラメータ

**形式**: `Dictionary<string, string>`形式で渡す

**アクセス方法**:
- テンプレート内で`@Model`としてアクセス可能
- `@dic` という簡潔なエイリアスも使用可能

**@マーク記法について**:
- Razorテンプレートでは、`@` で始まる記述はRazorコード（C#式）を表す
- `@dic["key"]` は、Razorエンジンに対して「dicという変数のkeyというキーの値を出力する」と指示
- Razorエンジンがこれを処理し、実際の値に置換して、HTMLに出力される

#### 3.4.3 パラメータ参照構文

**Dictionary形式**:
- `@dic["key"]` または `@Model["key"]`
  - `@` で始まることで、Razorエンジンが処理対象として認識
- キーが存在しない場合は空文字列を返す（エラーは発生しない）

**モデルプロパティ**（将来拡張用）:
- 将来的に強く型付けされたモデルを使用する場合、`@Model.PropertyName`形式でのアクセスを検討
- 現在のバージョンでは`Dictionary<string, string>`のみサポート

**配列アクセス**:
- 配列データはJSON文字列として`Dictionary<string, string>`に保存される
- Razorテンプレート内でJSON文字列をパースして使用
- 例: `@JsonSerializer.Deserialize<List<Item>>(Model["items"])[i].PropertyName`

#### 3.4.4 パラメータの型

**基本型**:
- すべて文字列（`Dictionary<string, string>`）
- 数値や日付も文字列として扱う

**配列データ**:
- JSON文字列として渡し、Razor内でパース
- 例: `@JsonSerializer.Deserialize<List<Customer>>(Model["customers"])`

**実装例**:
```csharp
// C#側
var parameters = new Dictionary<string, string>
{
    ["customerName"] = "山田太郎",
    ["amount"] = "10000",
    ["items"] = "[{\"name\":\"商品A\",\"price\":1000}]"
};
```

```razor
<!-- Razorテンプレート側 -->
<div>顧客名: @dic["customerName"]</div>
<div>金額: @dic["amount"]円</div>
@{
    var items = JsonSerializer.Deserialize<List<Item>>(dic["items"]);
}
@foreach(var item in items)
{
    <div>@item.Name: @item.Price円</div>
}
```

### 3.6 PDF変換

#### 3.6.1 変換方法

- **方法**: Playwright for .NET を使用
- **ブラウザ**: Chromium（Playwrightが自動ダウンロード）
- **処理フロー**:
  1. HTML文字列をメモリに保持
  2. Playwrightでヘッドレスブラウザを起動
  3. HTMLをブラウザに読み込み
  4. PDF出力
  5. バイト配列をファイルに保存

#### 3.6.2 出力

- **出力形式**: PDFファイルとして保存
- **保存ダイアログ**: ファイル保存ダイアログを表示
- **デフォルトファイル名**: テンプレート名 + ".pdf"
- **出力方式**: バイト配列として取得し、ユーザーがダウンロード

#### 3.6.3 PDF設定

**ページ設定**:
- 用紙サイズ（A4、A3、Letter等）- デフォルトは A4
- 向き（縦、横）- デフォルトは縦
- マージン - 上下左右各値を指定可能
- スケール（倍率）- デフォルトは 100%

**印刷品質設定**:
- 背景の印刷 - CSS背景色・画像を含める
- グラフィック - 画像やSVGの品質設定
- ヘッダー・フッター - カスタムヘッダー・フッターを追加可能

#### 3.6.4 初回セットアップ

- **Chromium ダウンロード**: 初回実行時に自動ダウンロード（約100MB）
- **ダウンロード位置**: ユーザーの .playwright ディレクトリ
- **トリガー**:
  - `await Playwright.CreateAsync()` 初回呼び出し時
  - または `playwright.ps1 install` PowerShell スクリプトで事前ダウンロード
- **インストーラー組み込み**: インストーラーに Chromium を組み込むことも可能

#### 3.6.5 実装例

```csharp
// PdfService.cs (Blazor Server 内)
using Microsoft.Playwright;

public class PdfService
{
    private readonly IPlaywright _playwright;

    public async Task<byte[]> GeneratePdfAsync(string html, PdfOptions options = null)
    {
        await using var browser = await _playwright.Chromium.LaunchAsync();
        var page = await browser.NewPageAsync();

        await page.SetContentAsync(html);

        var pdfOptions = options ?? new PdfOptions
        {
            Format = "A4",
            Margin = new PdfMargin { Top = "10mm", Right = "10mm", Bottom = "10mm", Left = "10mm" }
        };

        return await page.PdfAsync(pdfOptions);
    }
}
```

### 4.4 Generic HostとDI（Blazor Server）

#### 4.4.1 Generic Hostの使用

- **目的**: Blazor Server アプリケーションのホスティングと DI コンテナ管理
- **実装**: Blazor Server プロジェクトの `Program.cs` で `WebApplicationBuilder` を使用
- **利点**:
  - 統一されたサービス管理
  - ロギング、設定、DI の統合
  - ASP.NET Core としてのアプリケーションライフサイクル管理
  - Blazor Server との統合が自動

#### 4.4.2 依存性注入（DI）

- **DIコンテナ**: Microsoft.Extensions.DependencyInjectionを使用
- **サービス登録**: `Program.cs`の`ConfigureServices`でサービスを登録
- **注入方法**: コンストラクタインジェクションを使用
- **ロギング**: `ILogger<T>`を各クラスで注入して使用

#### 4.4.3 サービス登録例

```csharp
// Blazor Server Program.cs
var builder = WebApplication.CreateBuilder(args);

// Blazor Server の登録
builder.Services.AddRazorComponents()
    .AddInteractiveServerComponents();

// ロギングは自動的に登録される

// 状態管理サービス（Scoped: 各接続ごとに1インスタンス）
builder.Services.AddScoped<ApplicationStateService>();
builder.Services.AddScoped<DesignerStateService>();
builder.Services.AddScoped<PreviewService>();
builder.Services.AddScoped<ParameterService>();

// ビジネスロジックサービス（Singleton: アプリケーション全体で共有）
builder.Services.AddSingleton<LayoutJsonService>();
builder.Services.AddSingleton<HtmlRendererService>();

// Playwright PDF サービス（Singleton）
builder.Services.AddSingleton<PdfService>();

// ... その他のサービス

var app = builder.Build();

app.MapRazorComponents<App>()
    .AddInteractiveServerRenderMode();

app.Run();
```

#### 4.5.1 設定ファイル構成

**ファイル**: `appsettings.json`
**場所**: プロジェクトルートディレクトリ（Visual Studioのビルドプロセスで出力ディレクトリにコピー）
**用途**: アプリケーションの設定、表示分割数、サンプルデータパス、デフォルトパラメータ等の管理

#### 4.5.2 appsettings.jsonの構造

```json
{
  "Logging": {

  "RazorReportDesigner": {

      "DefaultColumns": 36,

      "A4Width": 793.7,
      "A4Height": 1122.52,
      "DPI": 96
    },
    "Layout": {
      "DefaultDisplayMode": "Draft",
      "SupportedDisplayModes": ["Draft", "Preview"]
    },
    "SampleData": {
      "BasePath": "Data/Samples",
      "Files": [
        {
          "name": "customers",
          "filename": "sample_customers.json"
        },
        {
          "name": "products",
          "filename": "sample_products.json"
        },
        {
          "name": "invoices",
          "filename": "sample_invoices.json"
        },
        {
```

#### 4.5.3 設定項目の説明

**Grid セクション**:
- `DefaultColumns`: 内部保存時の基本列数（常に36に固定）
- `DisplayColumns`: 表示時に選択可能な列数のリスト（36, 30, 24, 18から選択可能）
- `A4Width`, `A4Height`: A4用紙のサイズ（px）
- `DPI`: 画面のDPI（96を基準）

**Layout セクション**:
- `DefaultDisplayMode`: デザインビュー起動時の初期表示モード（"Draft" または "Preview"）
- `SupportedDisplayModes`: サポートされる表示モード

**SampleData セクション**:
- `BasePath`: サンプルデータファイルのベースディレクトリ（ビルド後の実行ディレクトリからの相対パス）
- `Files`: 利用可能なサンプルデータファイルのリスト

**Parameters セクション**:
- `DefaultValues`: アプリケーション起動時のデフォルトパラメータ値

#### 4.5.4 実装時の注意

- `appsettings.json` はプロジェクトの "Copy to Output Directory" を "Copy if newer" または "Always copy" に設定して、ビルド時に出力ディレクトリにコピーされるようにする
- 設定値はGeneric Hostの設定システムを使って `IConfiguration` インターフェースで読み込む
- リリースビルド用の `appsettings.Release.json` を別途用意することも検討

### 6.1 アーキテクチャ方針

#### 6.1.1 Blazor コンポーネントモデル

- **方針**: Blazor コンポーネントベースのアーキテクチャを採用
- **メリット**: Microsoft 純正 Razor エンジンの統合、将来的な Web 版対応容易
- **ステートフル**: 各コンポーネントは独立した状態を持つ
- **通信**: SignalR（自動）で WPF ↔ Blazor 間の通信を実装

#### 6.1.2 WPF と Blazor の役割分担

**WPF の責務**:
- Blazor Server プロセスの起動・停止管理
- WebView2 での Blazor Server ホスティング
- ウィンドウのライフサイクル管理

**Blazor Server の責務**:
- UI全体（Razor コンポーネント）
- ビジネスロジック（サービスクラス）
- HTML生成（Microsoft純正 Razor エンジン）
- PDF変換（Playwright）

#### 6.1.3 責務分離

**Model**（共有ライブラリ）:
- データ構造の定義
- グリッド計算等の汎用ロジック
- ビジネスロジック

**View（Blazor）**:
- Razor コンポーネント（.razor ファイル）
- UI の表示
- ユーザー入力の受け取り
- データバインディング

**Service（Blazor）**:
- 状態管理
- ビジネスロジックの実装
- 外部システムとの連携（JSON I/O、PDF生成等）

### 6.2 依存性注入（DI）

#### 6.2.1 Generic Hostの使用

- **ホスティング**: Generic Hostを使用してアプリケーションをホスト
- **DIコンテナ**: Microsoft.Extensions.DependencyInjectionを使用
- **設定**: `Program.cs`でサービスを登録し、DIコンテナを構築

#### 6.2.2 サービス登録

以下のサービスをDIコンテナに登録：

- **ILogger<T>**: ロギングサービス（各クラスで使用）
- **ApplicationStateService**: アプリケーション全体の状態管理
- **DesignerStateService**: デザイナーの状態管理
- **PreviewService**: プレビュー表示の管理
- **ParameterService**: パラメータ管理
- **LayoutJsonService**: JSON読み込み・保存
- **LayoutToRazorConverter**: JSON→Razor変換
- **HtmlRendererService**: HTML生成
- **その他のサービス**: 必要に応じて追加

#### 6.2.3 サービス注入

- **コンストラクタインジェクション**: 各クラスのコンストラクタで必要なサービスを注入
- **ILogger<T>**: 各クラスで`ILogger<T>`を注入してロギングを行う
- **サービス間の依存関係**: DIコンテナが自動的に解決

### 6.3 状態管理の責務

#### 6.3.1 ApplicationStateService

- アプリケーション全体の状態管理
- ビューモード切り替え（デザインビュー/プレビュービュー）
- ファイル操作（新規作成、開く、保存）

#### 6.3.2 DesignerStateService

- デザイン要素の管理
- グリッド設定（表示/非表示、分割数切り替え）
- 選択要素の管理
- 要素の追加・削除・移動
- レイアウト作成モード（仮組み/データ表示）の管理

#### 6.3.3 PreviewService

- プレビュー表示の管理
- HTML生成のトリガー
- WebView2の制御

#### 6.3.4 ParameterService

- パラメータの管理（`Dictionary<string, string>`）
- パラメータの追加・編集・削除
- サンプルデータの読み込み

## 7. 制約事項

### 7.1 ファイル形式

- レイアウトデータはJSON形式（`.rrd`または`.json`）で保存
- Razorテンプレートは直接保存せず、JSONから都度生成
- メタデータはJSONファイル内に含める

### 7.2 パラメータの型

- パラメータはすべて文字列型（`Dictionary<string, string>`）
- 数値や日付も文字列として扱う
- 型変換はRazorテンプレート内で行う

### 7.3 PDF変換

- PDF変換は Playwright for .NET を使用
- Chromium ブラウザエンジンに依存
- 初回実行時に約100MBの Chromium を自動ダウンロード
- インターネット接続が必要（初回セットアップ時のみ）
- ローカル処理のため、プライベートドキュメント情報は外部に送信されない

### 7.4 Blazor コンポーネント

- Razor コンポーネント（.razor ファイル）で UI を構築
- 各コンポーネントは独立した状態を持つ（Scoped Lifetime）
- パラメータの受け渡しは `@bind`、`@on{Event}` で実装
- JavaScript Interop で HTML5 Canvas/SVG 操作を実現

### 7.5 グリッドシステム

- すべてのコンポーネントの配置・サイズはグリッドセル単位で管理
- A4サイズを基準とした36列固定分割システム
- 位置とサイズはグリッドセル（column, row, columnSpan, rowSpan）で指定
- **データ保存**: JSONには常に36列基準でセル位置（column, row）とセルサイズ（columnSpan, rowSpan）を保存
- **デザインビュー表示**: appsettings.jsonの`DisplayColumns`で選択可能な分割数（36, 30, 24, 18列）で視覚的に表示
- **HTML生成**: JSONのセル情報をそのままCSSグリッド（`grid-column`, `grid-row`）で配置
  - ピクセル単位の計算は不要
  - CSSエンジンがセル配置を自動処理
- グリッド罫線はデフォルトでON（表示状態）
- スナップ機能は常に有効（オフにできない）
- すべての要素は必ずグリッドセルにスナップ（強制スナップ）
- グリッド範囲選択機能により、Excelライクな範囲選択が可能
- 範囲選択時のコンポーネント貼り付けとテーブル作成に対応

### 7.6 レイアウト編集

- WYSIWYG方式のみ（HTMLは直接編集不可）
- すべての編集は視覚的な操作で行う
- コンポーネントの配置、スタイル設定、プロパティ編集はすべてUI操作で実施

### 7.7 プラットフォーム

- Windows専用（WPFの制約）
- .NET 10.0以上が必要

### 7.8 Blazor Server の制約

- **SignalR 接続**: リアルタイム通信に SignalR を使用
  - localhost 接続なので実質的に遅延なし
  - デスクトップ版では問題なし（Web 版では考慮が必要）

- **JavaScript Interop**: ドラッグ&ドロップ等で JavaScript 相互運用が必要
  - HTML5 Canvas/SVG 操作は JavaScript で実装
  - Blazor C# コードから JavaScript 関数を呼び出し

- **セッション管理**: 各ユーザー接続がセッションを持つ
  - デスクトップ版では1ユーザー = 1セッション
  - 複数ウィンドウで別々のセッションが作成される可能性

### 7.9 Playwright の制約

- **Chromium ブラウザ**: PDF 生成には Chromium ブラウザが必要
  - 初回実行時に自動ダウンロード（約100MB、時間要）
  - インターネット接続が必要（初回セットアップ時のみ）

- **メモリ使用量**: Playwright ブラウザプロセスはメモリを消費
  - 大量の PDF 生成時には順序処理でメモリリークに注意
  - `await using` 文でリソースを確実に解放

- **パフォーマンス**: 初回起動時と PDF 生成時に CPU 使用率が高い
  - PDF 生成は バックグラウンドタスク化を検討
  - 同時実行数の制限を検討

## 8. エラーハンドリング

### 8.1 ファイル操作エラー

**読み込みエラー**:
- ファイルが存在しない場合: エラーメッセージを表示
- ファイル形式が不正な場合: エラーメッセージを表示
- アクセス権限がない場合: エラーメッセージを表示

**保存エラー**:
- ディスク容量不足: エラーメッセージを表示
- アクセス権限がない場合: エラーメッセージを表示
- ファイルがロックされている場合: エラーメッセージを表示

### 8.2 Razorテンプレートエラー

**コンパイルエラー**:
- シンタックスエラー: エラーメッセージと行番号を表示
- 型エラー: エラーメッセージを表示
- プレビュー更新時にエラーを検出

**実行時エラー**:
- パラメータが存在しない場合: 空文字列を返す（エラーは発生しない）
- 配列のインデックス範囲外: エラーメッセージを表示
- JSONパースエラー: エラーメッセージを表示

### 8.3 WebView2エラー

**初期化エラー**:
- WebView2ランタイムがインストールされていない場合: インストールを促すメッセージを表示
- 初期化に失敗した場合: エラーメッセージを表示

**Blazor Server 接続エラー**:
- Blazor Server が起動しない場合: 詳細メッセージを表示
- localhost 接続に失敗した場合: ポート競合の確認を促す

### 8.4 Blazor Server エラー

**起動エラー**:
- ポート競合: 別のプロセスが同じポート（5001等）を使用している場合は別ポートで起動
- アセンブリロードエラー: 必要な DLL が見つからない場合はエラーメッセージを表示

**SignalR 通信エラー**:
- 接続が切断された場合: 自動再接続を試みる
- タイムアウト: ユーザーに再接続を促す

### 8.5 Playwright エラー

**Chromium ダウンロードエラー**:
- インターネット接続がない場合: オフラインを知らせるメッセージ
- ダウンロード失敗: リトライ機能を提供
- ディスク容量不足: 空き容量確認を促す

**PDF 生成エラー**:
- HTML 処理エラー: エラーメッセージと該当する HTML の一部を表示
- メモリ不足: PDF 生成をキャンセルしてメモリ解放を促す
- タイムアウト: 大きな PDF のタイムアウト値を拡張

**ブラウザプロセス管理エラー**:
- プロセス起動失敗: エラーログを出力
- リソース解放失敗: メモリリーク警告

### 8.6 ユーザー入力エラー

**バリデーション**:
- 無効な値の入力: エラーメッセージを表示
- 必須項目の未入力: エラーメッセージを表示

**エラーメッセージの表示**:
- ツールバーにエラーアイコンを表示
- エラーパネルに詳細を表示（オプション）

## 9. パフォーマンス要件

### 9.1 レスポンス時間

- **UI操作**: 100ms以内に応答
- **プレビュー更新**: 1秒以内に表示開始
- **PDF変換**: 5秒以内に完了（ページ数による）

### 9.2 メモリ使用量

- **基本動作**: 150MB以下（WPF + Blazor Server）
- **大規模テンプレート**: 500MB以下
- **メモリリーク**: 長時間動作してもメモリ使用量が増加しない
- **Playwright PDF生成時**: 一時的に 200MB～500MB増加（ブラウザプロセス）
  - PDF生成完了後はプロセス終了でメモリ解放
  - 複数PDF生成時の順序処理でメモリ管理

### 9.3 ファイルサイズ

- **JSONファイル（.rrd / .json）**: 10MB以下を推奨
- **サンプルデータ**: 1MB以下を推奨

### 9.4 最適化

- **レンダリング**: 必要最小限の要素のみをレンダリング
- **フォント読み込み**: 使用されているフォントのみを読み込む
- **キャッシュ**: コンパイル済みテンプレートをキャッシュ（将来拡張）

### 12.3 設計方針

#### 12.3.1 レイアウトデータ管理

- レイアウトデータはJSON形式で管理
- Razorファイルとして直接保存せず、JSONから都度生成
- これにより、メタデータの管理が容易になり、将来の拡張性が向上

#### 12.3.2 アーキテクチャ（WPF + Blazor Server ハイブリッド）

**WPF の役割**:
- WebView2 による Blazor Server のホスティング
- ウィンドウのライフサイクル管理
- シンプルな実装に徹する

**Blazor Server の役割**:
- UI全体（Razor コンポーネント）
- ビジネスロジック
- HTML生成と PDF 変換

**共有ライブラリの役割**:
- ビジネスロジックと汎用モデル
- UI固有のコード（WPF, Blazor）は含まない

**DI と サービス管理**:
- Blazor Server の組み込み DI を使用
- Generic Host で統一的にサービス管理
- ILogger等のサービスは DI で注入

**デザイン原則**:
- シンプルな実装を優先
- 過度な抽象化を避ける
- 保守性と可読性を重視
- Microsoft 純正の Razor エンジンと Playwright を採用
- 将来的な Web 版対応を視野に入れた設計

### 12.4 今後の拡張予定

- **Web 版対応**: Blazor Server をそのまま Web サーバーでホスト可能な設計
  - WPF ホスト部分を除去するだけで Web 版として公開可能
