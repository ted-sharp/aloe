## 1. 概要

### 1.1 目的

RazorReportServerは、Blazor Serverアプリケーションで実装されたWYSIWYG（What You See Is What You Get）方式のレポートデザイナーです。
プレビューをHTML DOM上で構築しつつJSON形式でレイアウトデータを保存します。
Microsoft純正Razorエンジンでパラメータを渡してHTMLに変換します。完成したレポートはPlaywrightによるPDF変換で出力できます。

### 1.2 主な機能

- **Blazorベースの WYSIWYG デザイナー**: HTMLコンポーネントによるドラッグ&ドロップで直感的にレポートをデザイン
- **Microsoft 純正 Razor エンジン**: Blazor組み込みのテンプレートエンジンによる柔軟なデータバインディング
- **プレビュー機能**: デザイン内容をリアルタイムで表示・確認（同一ページ内表示）
- **PDF出力**: Playwright によるPDF変換（高度なレイアウト制御に対応）
- **グリッドシステム**: A4ベースのグリッド分割による整ったレイアウトのためのスナップ機能
- **リッチテキスト編集**: フォント、スタイル、色などの詳細なテキスト編集

### 2.2 データフロー

```
WPF (ホスト)
  │
  └─ WebView2
       │
       └─ Blazor Server（localhost:5001）
             │
             ├─ Blazor UI（Razor コンポーネント）
             │   ├─ ツールおよびパラメータパレット
             │   ├─ デザイナーエリア ← グリッドセルスナップ（常時有効）
             │   └─ プロパティパネル
             │
             └─ サーバーサイド処理
                 │
                 ├─ JSON処理（LayoutService）
                 │   │
                 │   └─ デザインモデル
                 │
                 ├─ HTML生成（HtmlRendererService）
                 │   │
                 │   ├─ Microsoft純正 Razor エンジン
                 │   │
                 │   └─ HTML（パラメータ適用済み）
                 │       │
                 │       └─ Blazorコンポーネントでプレビュー表示
                 │
                 └─ PDF変換（PdfService）
                     │
                     └─ Playwright（Edge）
                         │
                         └─ PDF出力
```

### 2.3 システム境界

- **入力**: ユーザーのマウス・キーボード操作（Blazor UI経由）、ファイル読み込み
- **出力**: JSONファイル（.rrd / .json）、PDFファイル
- **通信**: SignalR（Blazor Server ↔ WebView2（ブラウザ）、localhost内なので遅延なし）
- **中間生成物**: Razorテンプレート（メモリ上でのみ生成、直接保存はしない）
- **外部依存**: WebView2ランタイム、Blazor Server ランタイム、Playwright Edge

## 3. 機能仕様

### 3.1 UI構成

#### 3.1.1 レイアウト構造

#### 3.1.2 ビューモード

- **デザインビュー**（"Draft"モード）: レポートのレイアウト編集モード
  - HTML コンポーネント（CSSグリッド）で実装
  - グリッド表示（グリッド線ON）
  - コンポーネントの配置・編集
  - プロパティ編集
  - WYSIWYG方式のみ（HTMLは直接編集不可）

- **プレビュービュー**（"Preview"モード）: レンダリング結果の表示モード
  - HTML コンポーネント（CSSグリッド、グリッド線OFF）で表示
  - 実際のデータを適用したプレビュー

**用語の対応**: 「デザインビュー」= "Draft"モード、「プレビュービュー" = "Preview"モード。設定ファイルでは`DefaultDisplayMode`と`SupportedDisplayModes`で管理されます。

**WYSIWYG編集ポリシー**:
- HTMLは直接編集不可（WYSIWYGのみ）
- すべての編集は視覚的な操作で行う
- コンポーネントの配置、スタイル設定、プロパティ編集はすべてUI操作で実施

#### 3.1.3 ツールおよびパラメータパレット

- **位置**: 左側パネル
- **機能**: コンポーネント一覧とパラメータ管理を統合表示

**コンポーネント一覧**:
- テキスト
- 画像
- テーブル
- Razorコードブロック

**パラメータ管理**:
- 検索ボックス（絞り込み用）
- パラメータ一覧（キー・値の編集）
- パラメータの追加、編集、削除
- ドラッグ&ドロップでコンポーネントに配置可能

**操作**:
- コンポーネント: ドラッグ&ドロップでデザインエリアに配置
- パラメータ: ドラッグ&ドロップでコンポーネントに値を配置（自動的に`@dic["key"]`形式のRazorコードに変換）

**パラメータの配置ルール**:
- 通常はテキストコンポーネントとして、参照プロパティが設定された状態で配置される
- 画像キーの場合は画像コンポーネントとする
- 配列キーの場合はテーブルコンポーネントとする
- パラメータのリストはJSONで定義されているものとする

#### 3.1.4 ツールバー

**基本操作**:
- 新規作成
- ファイルを開く
- 保存
- プレビュー切り替え
- PDF出力
- グリッド罫線のON/OFF（トグルボタン、デフォルトON）
- グリッド分割数切り替え（36, 30, 24, 18列のドロップダウン）
- テーブル作成（範囲選択時に使用）

**フォントスタイル**:
- **Bold**（太字）
- **Italic**（斜体）
- **Underline**（下線）
- **Strikethrough**（取り消し線）

**フォント設定**:
- フォントファミリー選択ドロップダウン（Googleフォント含む）
- フォントサイズ選択
- フォントカラー選択（カラーピッカー）

**配置**:
- 左揃え
- 中央揃え
- 右揃え
- 両端揃え

**配置揃え**（複数選択時）:
- 上揃え、中央揃え（垂直）、下揃え
- 左揃え、中央揃え（水平）、右揃え
- （詳細は[3.2.5 配置揃え機能](#325-配置揃え機能)を参照）

#### 3.1.5 プロパティパネル

- **位置**: 右側パネル
- **機能**: 選択中の要素のプロパティを編集
- **表示条件**: 要素が選択されている場合のみ表示

#### 3.1.6 デザインエリア

- **位置**: 中央
- **実装**: Blazor Razorコンポーネント + CSSグリッド
- **機能**: レポートのデザイン編集領域
- **特徴**:
  - CSSグリッド（36列×51行）で直接レイアウト
  - グリッド線はCSS background-imageで自動描画
  - グリッド線のON/OFF切り替え可能（デフォルトON）
  - 要素配置時に必ずグリッドセルにスナップ（常時有効、オフ不可）
  - スクロール可能
  - グリッド範囲選択対応（Excelライクな範囲選択）
  - 範囲選択時のコンポーネント貼り付け対応
  - 範囲選択時のテーブル作成対応
  - 要素の複数選択対応（SHIFT+クリック）
  - 表示用分割数の切り替え（36, 30, 24, 18列）

#### 3.1.7 操作インタラクション

**キーボード操作**:
- Ctrl+C: コピー、Ctrl+V: ペースト、Delete: 削除、Escape: 選択解除
- Ctrl+Z/Y: 元に戻す/やり直す（将来拡張）

**マウス操作**:
- 左クリック: 要素選択、Shift+クリック: 複数選択
- ダブルクリック: コンポーネントの編集モード起動（テキスト=インライン編集、画像=ファイル選択、テーブル=セル編集）
- ドラッグ: グリッド範囲選択、コンポーネント移動
- 右クリック: コンテキストメニュー表示（コピー、切り取り、削除、複製、プロパティ、ペースト、すべて選択）

#### 3.1.8 デザインエリア拡張領域

**A4範囲外への配置**: A4範囲（36列×51行）外にもコンポーネント配置可能。デザイン時は無制限拡張、プレビュー/PDF出力時はA4外要素は非表示（警告アイコン表示）。JSON保存時はすべての要素位置を記録。

**複数選択操作**: 列/行ヘッダークリックで全体選択、ドラッグで範囲選択、Shift+クリックで範囲追加、Ctrl+Aで全選択、Escで選択解除。選択範囲は一括移動・削除・スタイル変更・コピー/ペーストが可能。選択セルはハイライト表示、選択範囲の数値情報（「3列×5行」など）を表示。

#### 3.1.9 フローティングパネル

**パネル構成**: ツールおよびパラメータパレット（左側）、プロパティパネル（右側）。各パネルはドラッグで移動、リサイズ、最小化/最大化が可能。パネルの位置・サイズはセッション中保持。プロパティパネルは要素選択時にリアルタイム表示、ツールおよびパラメータパレットはコンポーネントとパラメータの両方を管理し、ドラッグ&ドロップで配置可能。

### 3.2 デザイナー機能

#### 3.2.1 グリッドシステム

**基本方針**: A4サイズ（793.7px × 1122.52px、96dpi基準）を基準とした36列固定分割システム。内部データは常に36列基準で保存し、表示時のみ36/30/24/18列から選択可能。

**グリッド計算**（参考値）:
- 列幅 = 793.7 ÷ 36 = 22.05px（参考値、実際の配置は分割数のみを使用）
- 行高 = 22.05px（参考値、正方形に近づけるため、実際の配置は分割数のみを使用）
- 行数 = 51行（四捨五入、実際の配置は分割数のみを使用）

**注意**: グリッドデザインは分割数（36列×51行）のみを使用し、px値は参考値として記載しています。実際の配置はグリッドセル単位（column, row, columnSpan, rowSpan）で管理されます。

**配置方式**:
- すべてのコンポーネントはグリッドセル単位（column, row, columnSpan, rowSpan）で配置
- 要素の配置・移動・リサイズ時は常にグリッドセルにスナップ（常時有効、オフ不可）
- JSONにはセル位置とサイズを保存

**グリッド表示**:
- グリッド罫線はデフォルトON（ツールバーで切り替え可能）
- 表示分割数の切り替えは視覚的表現のみ（内部データは36列基準のまま）

**グリッド範囲選択**:
- Excelライクな範囲選択（ドラッグで複数セル選択）
- 選択範囲にコンポーネントを配置可能（選択範囲のサイズに合わせて自動配置）
- 選択範囲からテーブル作成可能（ツールバーの「テーブル作成」ボタン）

**実装**: Blazor Razorコンポーネント + CSSグリッド。JSONの `(column, row, columnSpan, rowSpan)` がCSSグリッド配置に直接変換される。

- フォント、サイズ、色、スタイルの設定

**プロパティ**:

- フォントファミリー
- フォントサイズ
- フォントカラー
- 背景色
- 配置（左、中央、右、両端）
- 位置（グリッドセル: column, row）
- サイズ（グリッドセル: columnSpan, rowSpan）

**編集方法**:

- プロパティパネルで詳細設定

##### 2. 画像コンポーネント

**機能**:

**操作**:

##### 3. テーブルコンポーネント

##### 4. Razorコードブロックコンポーネント

**機能**:
- C#コードの直接記述
- パラメータの参照（`@dic["key"]`形式を使用。将来的に`@Model["key"]`形式への変更の可能性あり）
- 条件分岐、ループなどの制御構文

**プロパティ**:
- コード内容
- 位置（グリッドセル: column, row）
- サイズ（グリッドセル: columnSpan, rowSpan）
- カスタムプロパティ（任意）

**操作**:
- ダブルクリックでコード編集ダイアログを開く

**使用例**:
```csharp
@if (dic.ContainsKey("showHeader"))
{
    <div>ヘッダー表示</div>
}
```

**注意**: パラメータ参照形式は現在`@dic["key"]`を使用していますが、将来的に`@Model["key"]`形式への変更の可能性があります。

##### 5. レイアウトコンポーネント

**コンテナ（div相当）**: 複数の要素をグループ化、背景色・ボーダー・パディングの設定。フレックスボックスやグリッドレイアウトの設定（将来拡張）。

**セクション（section相当）**:
- セマンティックなセクション区切り
- コンテナと同様のスタイル設定が可能

#### 3.2.3 テーブルコンポーネント

**実装方式**: HTMLテーブル（`<table>`タグ）を使用。

**テーブル作成**: 手動作成（行・列数を指定）またはグリッド範囲選択から作成（選択範囲の列数×行数のセルを持つテーブルが作成される）。

**テーブル編集**: 行・列の追加/削除、セルの結合/分割、セルの内容編集。スタイル設定（セル背景色、ボーダー、パディング、テキスト配置）。ヘッダー行の指定とスタイル設定。

**グリッドセル準拠**: テーブル全体の位置とサイズはグリッドセル単位で管理（column, row, columnSpan, rowSpan）。テーブル内で行・列を追加/削除しても、テーブル全体のサイズは自動的には変更されない（リサイズハンドルで手動調整が必要）。

#### 3.2.4 選択機能

**コンポーネント選択**: クリックで単一選択、Shift+クリックで複数選択、ドラッグで範囲選択、Ctrl+Aで全選択。選択されたコンポーネントには選択ハンドルを表示し、プロパティパネルにプロパティを表示。グリッド範囲選択の詳細は[3.2.1 グリッドシステム](#321-グリッドシステム)を参照。

#### 3.2.5 配置揃え機能

##### 配置コマンドボタン

ツールバーに配置揃え用のコマンドボタンを配置：

**垂直方向の配置**:
- **上揃え**: 選択された複数コントロールの上端を揃える
- **中央揃え（垂直）**: 選択された複数コントロールの垂直方向の中央を揃える
- **下揃え**: 選択された複数コントロールの下端を揃える

**水平方向の配置**:
- **左揃え**: 選択された複数コントロールの左端を揃える
- **中央揃え（水平）**: 選択された複数コントロールの水平方向の中央を揃える
- **右揃え**: 選択された複数コントロールの右端を揃える

##### 配置基準

- **基準コントロール**: 最後に選択されたコントロール（アクティブな選択）を基準とする
  - 通常のUI動作と一貫性を保つ
- **配置後の位置**: 必ずグリッドセルにスナップして配置（強制スナップ）
- **複数選択時のみ有効**: 2つ以上のコントロールが選択されている場合のみボタンが有効化

##### 実装詳細

- 配置コマンド実行時: すべての選択コントロールの位置を計算し、基準コントロールに合わせて配置
- 配置後: 必ずグリッドセル単位に丸める（現在の分割数のグリッドセルに合わせる）

#### 3.2.6 オブジェクトスナップ機能（将来拡張）

Altキーを押しながら他のコントロールにスナップ可能（将来拡張予定）。

#### 3.2.7 ダブルクリック編集機能

##### 全コンポーネント対応

すべてのコンポーネントでダブルクリックによる編集をサポート：

- **テキストコンポーネント**: ダブルクリックでインライン編集モード（テキスト内容の直接編集）
- **画像コンポーネント**: ダブルクリックで画像ファイル選択
- **テーブルコンポーネント**: ダブルクリックでセル編集モード（セル内のテキスト編集）
- **Razorコードブロック**: ダブルクリックでコード編集モード
- **コンテナ/セクション**: ダブルクリックでプロパティパネルを表示

##### 編集モード

- **インライン編集**: テキストコンポーネントやテーブルセルで、その場で編集可能な状態にする
- **モーダル編集**: 画像やコードブロックなど、複雑な編集が必要な場合はBlazor ダイアログで実装
- **編集終了**: Enterキー、Escキー、またはフォーカスアウトで編集終了

#### 3.2.8 ドラッグ&ドロップ機能

**コンポーネントの配置**: ツールおよびパラメータパレットからデザインエリアへドラッグ&ドロップで配置。グリッド範囲選択時は選択範囲に自動配置（選択範囲のサイズに合わせて配置）。ドロップ位置はグリッド座標に変換してJSONに追加。

**データの配置**: ツールおよびパラメータパレットからコンポーネントへドラッグ&ドロップで、自動的に`@dic["key"]`形式のRazorコードに変換。テキストコンポーネントは既存テキストに追加または置換、テーブルセルはセル内容を置換。

**コンポーネントの移動**: デザインエリア内でコンポーネントをドラッグして移動。グリッド座標に変換してJSONを更新。他のコンポーネントとの重なりは許可（z-indexで制御）。

**視覚的フィードバック**: ドラッグ中は半透明プレビュー表示、ドロップ可能領域をハイライト、スナップ位置を表示。

#### 3.2.9 WYSIWYGエディタ機能

**リッチテキスト編集**: テキストコンポーネント選択時にツールバーでフォントスタイル（Bold、Italic、Underline、Strikethrough）、フォント設定（ファミリー、サイズ、カラー）、配置（左、中央、右、両端）を設定可能。

**インライン編集**: テキストコンポーネントをダブルクリックでインライン編集モード起動。編集中もリアルタイムでスタイル反映。Enter/Escキーまたはフォーカスアウトで終了。

**スタイル適用範囲**: テキストの一部を選択してスタイル適用、またはコンポーネント全体にスタイル適用。

#### 3.2.10 フォント管理

**Googleフォント**: HTML出力時に使用されているGoogleフォントを自動検出し、`<link>`タグで読み込む。必要なフォントのみを読み込んでパフォーマンス最適化。

**フォント選択UI**: システムフォントとGoogleフォントを統合表示。プリセットフォント（Noto Sans JP、Roboto等）を提供。カスタムフォントURLの入力も可能。フォント選択時にプレビュー表示（日本語・英語の両方で確認）。

### 3.3 レイアウトデータ管理

#### 3.3.1 保存形式

- **ファイル形式**: JSON形式で保存
- **ファイル拡張子**: `.rrd`（RazorReportDesigner）または `.json`
- **エンコーディング**: UTF-8
- **管理方式**: Razorファイルとして直接管理せず、JSONで管理

#### 3.3.2 JSON構造

レイアウトデータは以下のJSON構造で保存：

```json
{
  "version": "1.0",
  "grid": { "columns": 36, "rows": 51, "columnWidth": 22.05, "rowHeight": 22.05 },
  "pageSize": { "width": 793.7, "height": 1122.52, "unit": "px", "dpi": 96 },
  "elements": [
    {
      "type": "TextElement",
      "id": "text-1",
      "position": { "column": 0, "row": 0, "columnSpan": 12, "rowSpan": 2 },
      "properties": { "text": "サンプルテキスト", "fontFamily": "Noto Sans JP", ... },
      "customProperties": {}
    }
  ],
  "metadata": { "createdAt": "...", "updatedAt": "...", "gridColumns": 36 }
}
```

**主要項目**: `grid`（グリッド設定、`columns`と`rows`が実際に使用され、`columnWidth`と`rowHeight`は参考値）、`pageSize`（A4サイズ情報、参考値）、`elements`（要素配列）、`metadata`（メタデータ）。各要素は`type`、`id`、`position`（column, row, columnSpan, rowSpan）、`properties`（要素固有のプロパティ）、`customProperties`を持つ。位置情報はグリッドセル単位（分割数）で管理されます。

#### 3.3.3 JSONからHTML/Razorへの変換

**変換タイミング**: プレビュー表示時、PDF出力時、エクスポート時。JSONデータを読み込み、Blazor RazorコンポーネントでHTMLに変換。

**変換処理**: JSONの各要素をCSSグリッドレイアウトで配置（`column` → `grid-column`, `row` → `grid-row`）。ルートコンテナは36列×51行のCSSグリッド。要素固有のプロパティ（フォント、色等）をスタイルとして反映。デザイン時と実行時は同じBlazorコンポーネントを使用（WYSIWYG原則）。

**パラメータ適用**: デザイン時はサンプル値を適用してリアルタイム表示、プレビュー時はグリッド線を非表示にして実際の出力イメージを表示、PDF出力時はパラメータ値を適用してHTML生成→PlaywrightでPDF変換。

### 3.4 Razorテンプレート

#### 3.4.1 生成方式

- **生成元**: JSONデータから自動生成
- **テンプレートエンジン**: Microsoft純正Razorエンジン（Blazor Server組み込み）
- **保存**: 直接保存はしない（JSONから都度生成）
- **一時処理**: メモリ上でテンプレートを生成・処理（一時ファイル不要）
- **メリット**: RazorLight等のサードパーティライブラリ不要、.NET標準機能として長期サポート

### 3.5 PDF変換

#### 3.5.1 変換方法

- **方法**: Playwright for .NET を使用
- **ブラウザ**: Microsoft Edge（Chromiumベース、システムにインストール済みのEdgeを使用）
- **処理フロー**:
  1. HTML文字列をメモリに保持
  2. PlaywrightでEdgeブラウザを起動（`Channel = "msedge"`を指定）
  3. HTMLをブラウザに読み込み
  4. PDF出力
  5. バイト配列をファイルに保存

#### 3.5.2 出力

- **出力形式**: PDFファイルとして保存
- **保存ダイアログ**: ファイル保存ダイアログを表示
- **デフォルトファイル名**: テンプレート名 + ".pdf"
- **出力方式**: バイト配列として取得し、ユーザーがダウンロード

#### 3.5.3 PDF設定

**ページ設定**:
- 用紙サイズ（A4、A3、Letter等）- デフォルトは A4
- 向き（縦、横）- デフォルトは縦
- マージン - 上下左右各値を指定可能
- スケール（倍率）- デフォルトは 100%

**印刷品質設定**:
- 背景の印刷 - CSS背景色・画像を含める
- グラフィック - 画像やSVGの品質設定
- ヘッダー・フッター - カスタムヘッダー・フッターを追加可能

#### 3.5.4 初回セットアップ

- **Edge使用**: システムにインストール済みのMicrosoft Edgeを使用（追加ダウンロード不要）
- **Playwrightドライバ**: 初回実行時にPlaywrightドライバを自動ダウンロード（約10MB）
- **ダウンロード位置**: ユーザーの .playwright ディレクトリ
- **トリガー**:
  - `await Playwright.CreateAsync()` 初回呼び出し時
  - または `playwright.ps1 install` PowerShell スクリプトで事前ダウンロード

#### 3.5.5 実装詳細

Playwright for .NETを使用し、Edgeブラウザを起動してHTMLをPDFに変換。実装詳細は[Playwright for .NET 公式ドキュメント](https://playwright.dev/dotnet/)を参照。

### 3.6 パラメータ管理

#### 3.6.1 UI

- **統合パネル**: ツールおよびパラメータパレット内でパラメータ管理を提供
- **表示形式**: キー・値のペアで編集可能
- **操作**: 追加、編集、削除が可能
- **ドラッグ&ドロップ対応**: ツールおよびパラメータパレットからコンポーネントへドラッグ&ドロップ可能

#### 3.6.2 形式

- **データ形式**: キー・値のペア
- **型**: すべて文字列（`Dictionary<string, string>`）
- **管理方式**: JSON形式で管理
  - パラメータキー一覧とサンプル値は`appsettings.parameters.json`で定義（[4.4.3 appsettings.parameters.jsonの構造](#443-appsettingsparametersjsonの構造)を参照）
  - パラメータをJSONファイルに保存・読み込み可能
- **実行時**: JSONから読み込んだパラメータは`Dictionary<string, string>`に変換されてメモリで管理

#### 3.6.3 ドラッグ&ドロップ

- **操作**: ツールおよびパラメータパレットからコンポーネントへ値をドラッグ&ドロップ
- **自動変換**: ドロップ時に `@dic["key"]` 形式のRazorコードに自動変換
- **対応コンポーネント**:
  - **テキストコンポーネント**: 既存テキストに `@dic["key"]` を追加、または置換
  - **テーブルセル**: セル内容を `@dic["key"]` に置換
  - **Razorコードブロック**: コード内に `@dic["key"]` を挿入
- **視覚的フィードバック**: ドラッグ中はドロップ可能なコンポーネントをハイライト表示

#### 3.6.4 インポート/エクスポート

パラメータのJSON/CSV形式でのインポート/エクスポート（将来拡張）。

### 3.7 パラメータのプレビュー

#### 3.7.1 プレビュー時のサンプル値使用

- **サンプル値の定義**: `appsettings.parameters.json`に各パラメータの`sampleValue`を定義（[4.4.3 appsettings.parameters.jsonの構造](#443-appsettingsparametersjsonの構造)を参照）
- **プレビュー動作**: プレビュー表示時は、`appsettings.parameters.json`に定義された`sampleValue`を自動的に使用してレンダリング
- **値の上書き**: ユーザーがツールおよびパラメータパレットで値を変更した場合は、変更後の値を使用

#### 3.7.2 パラメータ管理の動作

- **初期表示**: `appsettings.parameters.json`からキー一覧を読み込み、各キーの`sampleValue`を初期値として表示（ツールおよびパラメータパレット内）
- **値の編集**: ユーザーがツールおよびパラメータパレット内で値を編集可能
- **プレビュー反映**: 値の変更は即座にプレビューに反映される

### 4.5 設定管理

#### 4.4.1 設定ファイル構成

設定ファイルは以下のように分割して管理します：

**ファイル構成**:
- `appsettings.json`: 基本設定（Logging、Grid、Layoutなど）
- `appsettings.parameters.json`: パラメータキー一覧とサンプル値

**場所**: プロジェクトルートディレクトリ（Visual Studioのビルドプロセスで出力ディレクトリにコピー）

#### 4.4.2 appsettings.jsonの構造

```json
{
  "Logging": { ... },
  "RazorReportDesigner": {
    "Grid": {
      "DefaultColumns": 36,
      "DisplayColumns": [36, 30, 24, 18],
      "A4Width": 793.7,
      "A4Height": 1122.52,
      "DPI": 96
    },
    "Layout": {
      "DefaultDisplayMode": "Draft",
      "SupportedDisplayModes": ["Draft", "Preview"]
    }
  }
}
```

**Grid**: `DefaultColumns`（内部保存時の基本列数、常に36）、`DisplayColumns`（表示時に選択可能な列数）、`A4Width`/`A4Height`（A4用紙サイズpx）、`DPI`（96基準）。**Layout**: `DefaultDisplayMode`（初期表示モード）、`SupportedDisplayModes`（サポートされる表示モード）。

#### 4.4.3 appsettings.parameters.jsonの構造

パラメータキー一覧とサンプル値を定義：

```json
{
  "parameters": [
    {
      "key": "companyName",
      "displayName": "会社名",
      "sampleValue": "株式会社サンプル",
      "type": "string",
      "description": "会社名を指定します"
    },
    {
      "key": "date",
      "displayName": "日付",
      "sampleValue": "2026-01-24",
      "type": "date",
      "description": "日付を指定します"
    }
  ]
}
```

**項目**: `key`（Razorテンプレート内で`@dic["key"]`として参照。将来的に`@Model["key"]`形式への変更の可能性あり）、`displayName`（UI表示名）、`sampleValue`（プレビュー時に使用）、`type`（string, number, date, array等）、`description`（説明）。プレビュー時は`sampleValue`を自動使用（ツールおよびパラメータパレットで変更可能）。
